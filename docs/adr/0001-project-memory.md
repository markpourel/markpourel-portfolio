# ADR 0001 — Память проекта: локальный SQLite + проекция в Obsidian

- **Статус:** принято
- **Дата:** 2026-11-09
- **Этап:** 10 (Агентский контур)
- **Связано:** `scripts/memory.mjs`, `.agent/memory.sqlite`, `docs/runbook.md`

## Контекст

Новая сессия агента не должна начинаться с нуля: решения, задачи и итоги прошлых сессий нужны в контексте, а не в переписке. В vault уже есть память проектов (`Dashboard`, этапы, `Sessions.md`), но она человекочитаемая и не даёт структурных запросов. В OpenCode были `sessions.json` и `opencode.db`, но они не читаются агентом автоматически и не синхронизируются; в текущем контуре (DeepSeek Harness) собственной машинной памяти у проекта нет.

Этап 10 предполагает «память агента + зеркало в Obsidian», этап 11 — что копия памяти лежит в Obsidian. Отсюда модель: рабочая память локальная, долговременная копия — в vault.

## Решение

1. **Источник истины для машинной памяти** — `.agent/memory.sqlite` (локально, в `.gitignore`, в контейнер не попадает): таблицы `sessions`, `decisions`, `tasks`, `artifacts` + полнотекстовый индекс FTS5.
2. **Единственный интерфейс** — `scripts/memory.mjs` (`init`, `session-start/close`, `add-decision`, `task(s)`, `attach`, `search`, `export`, `verify`). Без зависимостей, на `node:sqlite`.
3. **Obsidian — односторонняя проекция**: `Sessions/<id>.md` и `Decisions/<id>-<slug>.md` с `generated: true`. Экспорт идемпотентен и не перезаписывает файлы, созданные руками.
4. **Решения текстом** — `docs/adr/NNNN-*.md` в Git; путь хранится в `decisions.adr_path`, `verify` проверяет его существование.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Только markdown в vault, без БД | Поиск глазами; нельзя ответить «все решения по этапу 6», «что заблокировано» |
| JSONL + grep | Дёшево, но нет ранжирования и структуры; остаётся как путь отката |
| Markdown — источник, SQLite — индекс (`rebuild`) | Обратный парсер markdown — самая ломкая часть; противоречит бэкап-модели (этап 11: копия памяти в Obsidian) |
| Не делать память вовсе | Каждая сессия собирает контекст из 12 заметок; решения остаются в переписке |

## Последствия

- Плюс: поиск по решениям/задачам/сессиям за один вызов; структура для «что решили и почему»; ADR остаются ревьюируемыми в Git.
- Плюс: база локальная — публичный репозиторий не затрагивается, секреты в память не пишутся.
- Минус: база бинарная и не диффится; при переезде на другую машину её нужно восстановить из проекции (Sessions/Decisions) — потери структуры приемлемы.
- Минус: работает только там, где есть Node ≥ 22.5 (`node:sqlite`, на Node 22 — с флагом `--experimental-sqlite`); в CI и Docker не участвует.

## Инварианты

- Экспорт — только из базы в vault, никогда наоборот.
- Ручные заметки (`Dashboard`, этапы) не генерируются и не перезаписываются.
- Совпадение id: `YYYY-MM-DD-NN`, последовательность в пределах дня.
- Секреты, токены и приватные логи в память не попадают.

# ADR 0002 — Отказ от staging: публикация сразу в `main`

- **Статус:** принято
- **Дата:** 2026-11-11
- **Этап:** 04В
- **Связано:** `docs/runbook.md` § «Публикация изменения», ветка `feature/stage-4v-staging`

## Контекст

План ([[Новая схема выполнения плана]], §5) вводил этап 04В — второе приложение App Platform
из ветки `staging`, домен `staging.markpourel.ru` за Basic Auth и `noindex`, чтобы недоделанное
не попадало на публичный домен. Код защиты был написан и проверен локально (e2e: 401 без пароля,
200 с паролем, health без пароля, `Disallow: /`, `X-Robots-Tag`), приложение не создавалось.

Стоимость второго приложения — 510 ₽/мес при балансе 454,85 ₽ и текущих расходах ~589 ₽/мес.
Дешевле нет: VPS у Timeweb — от 1180 ₽/мес, превью-окружения платформы через API не подтверждены.

## Решение

Владелец 2026-11-11 отказался от отдельного staging: все изменения идут сразу в `main` через PR,
без второго платного приложения и лишних действий. Код защиты staging остаётся в ветке
`feature/stage-4v-staging` и в `main` не вливается.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Второе приложение staging, 510 ₽/мес | Владелец не готов платить за второе окружение |
| VPS + Caddy/Docker (резерв этапа 11) | Дороже (от 1180 ₽/мес) и добавляет ручную эксплуатацию |
| Превью-окружения платформы | Через API не подтверждены; рассчитывать на них нельзя |
| Проверять только локально, без staging | Принято: CI, постраничные Gate и revert-PR |

## Последствия

- Плюс: нет второй платной единицы инфраструктуры и лишних шагов в процессе.
- Минус: merge в `main` публикуется сразу — недоделанная страница или сломанный заголовок
  видны посетителям до отката.
- Минус: форма и 152-ФЗ (этап 7) проверяются на проде; до готовности форма не публикуется.
- Смягчение: недоделанные страницы не публикуются и не получают ссылок (постраничный Gate,
  этап 6); каждый PR обязан оставлять прод рабочим; откат — revert-PR или деплой предыдущего
  коммита.
- Возврат staging — один PR из ветки `feature/stage-4v-staging`: защита включается переменной
  `STAGING_BASIC_AUTH` в env второго приложения.

## Инварианты

- Секретов staging в репозитории нет; `STAGING_BASIC_AUTH` нигде не задан.
- Платные ресурсы создаются только с явного согласия владельца.

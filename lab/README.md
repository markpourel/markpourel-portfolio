# Лаборатория (песочница)

Отдельное Next.js-приложение для проверки библиотек и идей **до** того, как они
попадут на сайт.

- Это **не** workspace корня: собственные `package.json` и `package-lock.json`.
  Корневые `package.json` / `package-lock.json` не меняются.
- Порт **3100**, только localhost: `next dev -p 3100`.
- В сборку сайта, Docker-образ, CI и Dependabot не входит.
- Секретов, env прода и доступа к платформе здесь нет и быть не должно.

## Запуск (Windows, PowerShell)

```powershell
cd lab
npm ci
npm run dev      # http://localhost:3100
```

Другие команды:

```powershell
npm run build      # проверка сборки песочницы
npm run lint       # eslint песочницы (независим от корня)
npm run typecheck  # next typegen + tsc --noEmit
```

Установка библиотеки для эксперимента:

```powershell
cd lab
npm install --save-exact <пакет>
```

## Как добавить эксперимент

1. Скопировать `app/experiments/template/` в `app/experiments/<имя>/`
   (имя — латиницей, через дефис, без пробелов и без `_` в начале:
   папки с `_` Next считает private folders и не маршрутизирует).
2. Дописать `README.md` по шаблону: что проверяем, какая библиотека, вывод.
3. Добавить запись в список `app/experiments.ts` — главная страница берёт
   эксперименты оттуда.
4. Открыть http://localhost:3100/experiments/<имя>/.

Эксперимент считается законченным, когда в его `README.md` есть вывод:
подходит или нет. Незаконченный эксперимент остаётся в `lab/` и на сайт
не переносится.

## `lab/.local/` — локальные тяжёлые файлы

Папка в `.gitignore`. Для шрифтов без веб-лицензии, больших ассетов,
выгрузок макета и всего, что нельзя коммитить в публичный репозиторий.
В Git `lab/` попадает только код.

Подключение локальных файлов из `app/`:

- файл нужен только при `next dev` — ссылка через `new URL("../../.local/x.woff2", import.meta.url)`;
- файл нужен при `next build` — читать из `app/` нельзя, Next не соберёт
  проект; для сборки такой ассет должен лежать в `public/` (тоже под
  `.gitignore`), а в README эксперимента — пометка «ассет локальный».

Если лицензия не разрешает даже локальное подключение — эксперимент
закрывается в README без запуска, без файла.

## Правило переноса из `lab/` на сайт

Ничего из `lab/` не попадает на сайт автоматически. Перенос — отдельное
решение, и у каждой части свой порядок.

### Код (компонент, хук, визуальный приём)

1. Код из эксперимента попадает в `src/` **только отдельным PR**.
2. PR открывается **после постраничного Gate** (этап 6): для маршрута есть
   кадры 1440 и 360, контент и состояния, и владелец Gate принял.
   Страница без Gate не публикуется и не получает ссылок
   ([[Этап 06 — Страницы и UI]], правило 11).
3. Merge в `main` сразу уходит в прод (ADR 0002), поэтому эксперимент,
   который не готов к показу, в `src/` не переносится «на всякий случай».
4. Дизайн-значения берутся из макета владельца, а не из песочницы.

### Библиотека (зависимость)

1. Библиотека добавляется в корневой `package.json` **только после выбора**:
   в README эксперимента записано, зачем она нужна и что отвергнуто.
2. Версия — **точная** (без `^` и `~`), lock-файл обновляется в том же PR.
3. `npm run build` в корне и сборка Docker-образа проходят (CI: job
   `Docker Build`).
4. Проверены **лицензия** (совместима с публичным репозиторием) и **размер
   бандла**: рост JS первой загрузки относительно baseline этапа 6.1
   записан в отчёте PR.
5. Одна библиотека — один PR: проще откатить revert-PR.

### Ассеты и шрифты

1. В Git попадают только ассеты и шрифты с **подтверждённой веб-лицензией**.
2. Шрифт без веб-лицензии, исходники макета и `.fig` в репозиторий не
   попадают: они лежат в `lab/.local/` или вне репозитория.
3. Для шрифта в PR указывается файл лицензии и разрешённые форматы
   (как для `public/fonts/lebowski/LICENSE.rtf` в `docs/design-spec.md`).

## Отчёт по эксперименту

`README.md` эксперимента отвечает на три вопроса и больше не содержит:
что проверяли, какая библиотека и версия, какой вывод и что переносим
(или почему не переносим).

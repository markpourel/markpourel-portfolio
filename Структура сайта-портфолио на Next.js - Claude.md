### Что в присланной инструкции верно, а что поправить

- **Dockerfile лучше пресета Next.js.** App Platform деплоит из Git либо по выбранному стеку, либо по твоему Dockerfile. Свой Dockerfile даёт воспроизводимость, агент может править его сам, и тот же образ потом запустится на VPS. Нужны `output: 'standalone'` в next.config, multi-stage сборка, непривилегированный пользователь и `sharp` в зависимостях. Контейнеру обязательно нужны `HOSTNAME=0.0.0.0` и порт из переменной `PORT`, иначе он не ответит снаружи. [habr](https://habr.com/ru/articles/1011224)
- **Домен и VPS покупать не нужно, они у тебя уже есть.** Нужен только App Platform. В reg.ru добавляешь A- или CNAME-запись на адрес, который покажет панель Timeweb.
- **Цен в инструкции нет, и я их не проверяла.** Смотри калькулятор в панели. Сборка Next ест больше памяти, чем запуск, так что при падении по памяти поднимай тариф на ступень.
- **Dokploy и Coolify на твоём VPS не стоит ставить.** Для обоих заявлен минимум 2 ядра, 2 GB RAM и 30 GB диска, а у тебя 10 GB, и слои Docker будут копиться. Если захочешь деплоить на VPS, лучше Docker Compose + Caddy с готовым образом из GHCR или Kamal 2: он управляется из CLI и почти ничего не держит на сервере. [hostinger](https://www.hostinger.com/tutorials/?p=117422)[bitdoze](https://bitdoze.com/coolify-vs-dokploy-vs-kamal-2/)

### Обновлённая схема деплоя

GitHub (приватный репозиторий) → PR → CI в GitHub Actions (typecheck, lint, build, Playwright) → merge в `main` с обязательными проверками → App Platform сам собирает и выкатывает `main`.

Я не нашла подтверждения, что у App Platform есть предпросмотр на каждую ветку, как у Vercel, поэтому проверь это в панели. Если нет, замена — второй App на ветке `staging` с поддоменом.

### Доступ агента

- **Timeweb Cloud.** У платформы есть официальный MCP: он даёт агентам доступ к инфраструктуре, но не умеет удалять ресурсы, а изменяющие действия требуют подтверждения. Для сценария «агент деплоит сам» это удобные предохранители. Токен выпускается в разделе «API и Terraform», и права токена можно ограничить. В документации адрес MCP указан в двух вариантах, поэтому агент должен брать актуальный со страницы документации. Запасной путь: CLI `twc` ставится через pip или pipx и настраивается командой `twc config` с тем же токеном. [timeweb cloud mcp +2](https://timeweb.cloud/docs/ai-agents/timeweb-cloud-mcp.md)
- **GitHub** без изменений: fine-grained токен на один репозиторий и защищённый `main`.
- **reg.ru:** DNS правится руками один раз.
- **Скиллы из каталогов** ставь осторожно. Там есть скилл для деплоя на Timeweb (App Platform и VPS, домены, DNS, SSL, GitHub Actions). Перед установкой прочитай его целиком. Надёжнее написать свой короткий скилл `deploy` по документации Timeweb. [skills](https://skills.cat/category/docker?page=58)

### Что ещё меняется

- **Аналитика:** вместо Vercel Analytics подойдут Umami или Яндекс.Метрика.
- **Форма контактов.** Resend зарубежный, поэтому проверь доставляемость и вопросы с персональными данными по 152-ФЗ (я не юрист). Запасные варианты: бот в Telegram или SMTP российского провайдера.
- **Роль VPS:** внешняя точка мониторинга (Uptime Kuma смотрит на сайт из Швеции), аналитика и запасной контур. Доступность шведского VPS из РФ зависит от его оператора и твоего провайдера. По сообщениям, ограничения затрагивали и часть зарубежных хостеров, включая Hetzner, OVH и DigitalOcean, поэтому проверь доступность из нескольких сетей. [heise](https://heise.de/-10465087)
- **Структура папки:** `infra/` теперь содержит Dockerfile, `.dockerignore` и compose для VPS, в `.github/workflows/` лежит `ci.yml`, а скилл `deploy` работает с Timeweb вместо Vercel.

Что сделать

# Закрытие сессии

## Когда применять

В конце рабочей сессии над проектом `markpourel-portfolio-next`, до отчёта пользователю. Если сессия была короткой и без решений, шаги 2–3 пропускаются, шаги 1 и 5 обязательны.

## Шаги

1. **Проверить память.**
   ```bash
   node scripts/memory.mjs verify
   ```
   Если база не создана — `node scripts/memory.mjs init --vault C:\Obsidian\markpourel`.

2. **Записать решения.** Каждое решение, которое меняет код, дизайн, схему или процесс:
   ```bash
   node scripts/memory.mjs add-decision --stage <N> --title "<что решили>" --why "<почему>" [--alternatives "<что отбросили>"] [--adr docs/adr/NNNN-*.md] [--session <id>]
   ```
   Архитектурное решение дополнительно оформляется файлом в `docs/adr/` (в Git), путь передаётся в `--adr`.

3. **Обновить задачи.** Создавать только то, что осталось делать; закрывать сделанное:
   ```bash
   node scripts/memory.mjs task --stage <N> --title "<задача>" [--status blocked]
   node scripts/memory.mjs task --id <id> --status done
   ```

4. **Закрыть сессию.**
   ```bash
   node scripts/memory.mjs session-close --summary "<итог в 1–2 фразы>" --files "<файлы через запятую>"
   ```

5. **Спроецировать в Obsidian и проверить.**
   ```bash
   node scripts/memory.mjs export
   node scripts/memory.mjs verify
   ```
   Ожидаемо: `пропущено 0` (если не 0 — файл правился руками, разобраться, а не перезаписывать) и `ok`.

## Запреты

- Не писать в память секреты, токены, персональные данные и полные логи.
- Не править файлы с `generated: true` в `Sessions/` и `Decisions/` — правка потеряется при следующем экспорте; менять нужно запись в базе.
- Не переносить в память содержимое заметок этапов — там статусы и планы, а не решения сессии.
- Не закрывать сессию без `--summary`: без сводки она не находится поиском.
